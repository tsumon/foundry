# 本体、知识图谱与内嵌图存储

## 目标和边界

Foundry 的项目、任务、计划、候选、测试、审批和交付记录已有业务事实。本次把这些事实组织成可查询、可追溯的知识图谱，服务工作台和 Agent 的任务上下文。使用已有 SQLite 实现持久化属性图、关系索引和有界递归遍历；无需安装 Neo4j、Docker 或数据库服务。这里的“图数据库”是内嵌属性图存储与查询层，不宣称支持 Cypher、SPARQL 或外部图数据库兼容协议。

本体是版本化的类型、关系及校验规则；知识图谱是由真实业务记录投影的节点、边和来源；图存储负责事务、索引、查询与重建。三层均落地，不引入另一个 Agent 或改换执行底座。

## 数据及权限

- 内置本体覆盖项目、交付目标、环境、资源、任务、仓库、文件、计划、步骤、候选、测试证据、评审、审批与交付。关系限定合法起止类型，并记录来源 ID、版本和历史标识。
- 业务表继续是权威数据；新增 `knowledge_*` 表仅保存可重建的派生数据。同步在单个事务内读取业务快照、校验投影和替换图谱，失败回滚，不修改原任务或原始证据。
- 证据沿用 `EffectiveSource()`：模拟、隔离执行、来源未知分别显示。图谱连接、历史记录和模型推断不生成审批、不证明测试通过。
- 不投影凭据、账户配置、原始提示词、文件全文、测试输出、资源账号或外部标识。图谱本地查询不发起网络请求、模型调用或 VM 执行。
- 模型上下文只添加当前任务已有且已授权内容的结构化关系，不发送其他任务、项目或账户资料；既有上下文和执行审批仍然生效。
- 所有图谱 API 沿用会话、同源和恢复只读边界；重建只修改派生表。C4 限制运行时不新增能力授权。

## 查询与工作台

现有工作台增加“知识图谱”入口，提供项目/任务/类型/关键词筛选、邻接探索、影响范围与证据追溯。关系视图配套可键盘访问的列表、节点详情和回到原任务/项目的链接。本体页显示类型、关系和规则。显示来源版本、同步时间、图存储类型和截断信息，不用示例数据填充空状态。

查询使用参数化 SQL；遍历限制深度及节点数，不开放任意 SQL、脚本或远端查询。索引按节点类型、项目、任务和边两端建立。图谱损坏或版本不支持时明确报错，可从业务数据重建；不回写业务表，也不把不完整投影视为完整结果。

## 实施计划与验收

1. 本体与投影：固定类型/关系、稳定 ID、来源和历史语义；覆盖空库、悬空关系、非法类型、模拟来源、归档及敏感字段排除的离线测试。
2. 持久化与 API：增加图表/索引、事务同步、过滤及递归查询、重建和认证测试；验证重开数据库、删除/更新传播、失败回滚及原业务记录不变。
3. 工作台与 Agent：图谱浏览、本体说明、源记录跳转；为模型输入增加有界任务关系上下文，验证无跨任务泄漏及原审批不变。
4. 集成验收：Go 与前端回归、构建、静态检查、浏览器真实页面验收；同步中英 README。集中提交与 CI，失败继续修复，不进行真实模型或 VM 验收，不生成多份桌面产物。

## 实现契约

核心包 `internal/knowledge` 不依赖 store/engine/httpapi。`Project(Source)` 返回经过校验的节点及边；`Validate(Graph)` 校验本体约束；`TaskContext(Mission)` 返回限于当前任务的上下文。`internal/store/knowledge.go` 管理同步和查询。前端通过 `/api/knowledge/schema`、`/api/knowledge` 和 `/api/knowledge/rebuild` 使用该能力。

本版本不自动读取仓库未授权文件，不通过 LLM 猜测业务事实，不做 OWL 推理或任意本体编辑。新增领域类型通过版本化代码迁移，避免用户修改图结构绕过执行审批。

## 使用与维护

1. 从侧栏进入“知识图谱”，或在项目、任务中打开对应图谱。选择项目、任务、节点类型或关键词即可收窄结果。
2. 选择节点查看来源与版本；“以此节点探索”结合方向和深度执行有界遍历。影响范围沿已记录的关系向下展开，不推测未扫描的代码依赖；证据追溯沿上游关系返回记录来源。
3. “打开源任务/项目”返回原工作台。审批仍在原任务完成，图谱中没有执行或批准操作。
4. “本体与存储”显示完整类型与合法关系。重建从现有业务表重新投影，不运行模型、测试或工具，也不重置预算。恢复只读模式禁止重建。

正常读取会按最新业务快照同步；未变化时不重写。图谱校验失败会明确报错，使用重建可修复派生记录，原始业务数据仍须有效。首次升级仅新增 `knowledge_meta`、`knowledge_nodes`、`knowledge_edges` 及其索引，不改旧任务 JSON。

遍历深度为 1–4，返回最多 200 个节点，遍历工作上限 10,001 个节点/深度状态；触及上限明确显示截断。关系图预览最多 16 个相连节点，其余结果保留在列表。模型上下文最多 60 个节点、100 条边，截断明确标记。

计划新建的文件标记 `planned`，不宣称文件已经存在。仅由证据引用、没有候选快照记录的候选标记 `referenced`；历史测试不能证明当前候选通过。`plan_proposal` 记录不产生 `approved_by` 边，只有已有执行审批记录按计划修订号关联；关联仍不证明该审批当前可用于执行。

本功能无新增运行依赖。SQLite 负责持久化和事务，本体与投影在 Go 中实现；这是一套本地交付领域属性图，不是通用 OWL 推理器、向量数据库或第三方数据库协议兼容层。
